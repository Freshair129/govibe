## 4. Root Cause Analysis (การวิเคราะห์สาเหตุที่แท้จริง)
*ใช้เทคนิค 5 Whys เพื่อเจาะลึกหาสาเหตุที่แท้จริง ไม่ใช่แค่สาเหตุที่ตาเห็น*

1. **Why? (ทำไมระบบถึงล่ม):** เพราะ CPU ของ Database พุ่งขึ้น 100%
2. **Why? (ทำไม CPU ถึงพุ่ง 100%):** เพราะมีการรัน Query ดึงข้อมูล User ทั้งหมดโดยไม่มีการจำกัดจำนวน (No Limit/Pagination)
3. **Why? (ทำไมถึงมี Query แบบนั้นหลุดขึ้นไปบน Production):** เพราะในโค้ด API ดึงข้อมูล Report ไม่ได้เขียน Limit ไว้
4. **Why? (ทำไมตอน Test ถึงไม่เจอพฤติกรรมนี้):** เพราะในฐานข้อมูล Test (Staging) มีข้อมูล User แค่ 50 คน แต่ใน Production มี 500,000 คน ทำให้ตอน Test ดูเหมือนระบบทำงานได้ปกติ
5. **Why? (ทำไมโค้ดนี้ถึงผ่านมารันได้):** เพราะไม่มีระบบ Automated Test (Load Testing) ตรวจสอบประสิทธิภาพของ API ก่อนปล่อยขึ้น Production

**Root Cause (สาเหตุที่แท้จริง):** 
1. ขาดการทำ Pagination ในระดับ Code (Human Error)
2. สภาพแวดล้อมการทดสอบ (Staging) ไม่สะท้อนขนาดข้อมูลจริง (Process Flaw)

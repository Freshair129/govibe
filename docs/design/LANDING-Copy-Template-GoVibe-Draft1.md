## 5. CAPABILITIES (แทน Certifications)
- **Headline:** ความสามารถหลัก (Core Capabilities)
- **Subheadline:** Governed by design
- **Body:** GoVibe เป็น "ชั้นประสานงาน" (coordination layer) ไม่ใช่ตัวแทน coding agent ภายนอก — คุณคุมทีม agent หลายทีมได้โดยไม่ต้องยุ่งกับ billing หรือ quota ของ provider

**รายการความสามารถ:**
- MISSION CONTROL — ศูนย์บัญชาการ visual แบบ real-time
- DOCS-TO-CODE — เอกสารขับเคลื่อน task และ context
- DIAGRAM-TO-DOC — ไดอะแกรมกลายเป็นเอกสารที่รีวิวได้
- AGENT TEAM MGMT — จัดการ identity, role, authority, handoff
- RBAC + ABAC — คุม access ของคนและ agent แยกชั้น
- GENESIS KNOWLEDGE — atom, symbol graph, JIT context (MemoryOS V3)
- EXECUTION GOVERNANCE — ระบุ process complexity (`C-0`–`C-3`) และ Access Scope (`H0`–`H4`); Retrieval radius (`R`), compaction/resolution depth (`D`), fan-out (`W`), Budget และ Risk แยกกันใน work packet ตาม `docs/STD-Execution-Governance.md`

## 13. FAQ
- **Headline:** FAQs · **Subheading:** คำถามที่พบบ่อย
- **Intro:** หาสิ่งที่ต้องการไม่เจอใช่ไหม? ทีมเราพร้อมตอบคำถามเฉพาะโปรเจกต์ของคุณ
- **Response stat:** ตอบกลับภายใน `[[PLACEHOLDER]]`

**Q1: GoVibe แทนที่ Claude Code / Gemini CLI ของผมไหม?**
A: ไม่ — GoVibe เป็นชั้นประสานงาน ไม่จัดการ billing หรือแทนที่เครื่องมือ coding ภายนอก คุณใช้ของเดิมต่อได้

**Q2: ข้อมูลบนบอร์ดมาจากไหน?**
A: มาจากไฟล์เอกสาร Markdown/HTML ที่อนุมัติแล้วใน `docs/roadmap/` — ไม่มี mock data ตามกฎ live-data-only

**Q3: ต้องเขียน Genesis atom เองไหม?**
A: ไม่ต้อง — atom ถูกสกัดจากเอกสาร SWE ที่อ่านได้สำหรับมนุษย์โดยอัตโนมัติหลังเขียนเสร็จ

**Q4: external executor อนุมัติงานเองได้ไหม?**
A: ไม่ได้ — output ของ executor ภายนอกเป็นงานร่าง (draft) เสมอ ต้องผ่าน lead review, QA และ audit ก่อนปิดงาน

**Q5: รันแบบ local ได้ไหม?**
A: ได้ — มี HTTP/WS sidecar ที่ `127.0.0.1:4310` รองรับ Ollama local runtime ไม่ผูกกับ cloud
